# Знання про Drupal і ddev

Уроки, які підтвердились на реальних мультисайт-проєктах. Кожен пункт: симптом, причина, що робити.

## Кеші

### Після зміни Twig, JS чи CSS нічого не видно

- Перебудовуй кеш саме того сайту: `ddev drush @<alias> cr`. На мультисайті голий `drush cr` б'є в сайт за замовчуванням, у налаштуваннях якого може стояти null cache backend, а сайт, який ти дивишся, лишається з кешем.
- Перевір, чи стоїть перед сайтом Varnish (`docker ps`, заголовки відповіді `x-varnish`, `age`). `drush cr` Varnish не чистить: перезапусти контейнер Varnish.
- Браузер або Varnish можуть кешувати сторінки на добу. Перш ніж оцінювати зміну CSS чи розмітки, додай одноразовий параметр у URL (`?nc=1`).
- Одразу після `cr` OPcache може віддавати старий PHP до кінця вікна ревалідації (часто 60 с). Перебудова в цьому вікні може закешувати застарілі реалізації hooks. Зачекай або перезапусти php-fpm і перебудуй ще раз.

### 500 після перебудови кешу або перемикання гілки

Застарілий скомпільований container (`ServiceNotFoundException`) часто не лікується `drush cr`, бо самій перебудові потрібен bootstrap. Почисти всі три рівні в такому порядку:

1. Очисти (`TRUNCATE`) кожну таблицю `cache*` у базі цього сайту.
2. `FLUSHALL` у Redis (з паролем, інакше `NOAUTH`).
3. Перезапусти php-fpm у web-контейнері: container ще кешується в APCu і переживає обидва попередні кроки.

Також: сайт, у локальних налаштуваннях якого стоїть `cache.backend.null`, ламається, якщо bootstrap container від Redis цього сервісу не визначає. Використовуй `cache.backend.memory`: він так само не зберігає дані між запитами.

### 503 на всіх локальних сайтах одразу після `ddev restart`

Varnish визначає IP backend за іменем хоста один раз, під час завантаження VCL. Якщо перестворено лише web-контейнер, він отримує новий IP, а Varnish і далі стукає в старий (миттєвий `Connection refused`). Перезапусти контейнер Varnish.

## Шаблони, CSS і JS

### Відредагований шаблон не той, що рендериться

Суфікс у назві файлу чи CSS-класі (`-de`, `-updated`) нічого не каже про те, який шаблон рендериться. Знайди grep-ом ім'я `#theme` hook у PHP-контролерах і preprocess-функціях, щоб побачити, який варіант вибирається для сайту.

### CSS базової бібліотеки раптом вантажиться після CSS блоків (Drupal 10.4+)

Core тепер сортує бібліотеки за назвою в межах однакової ваги, тож базовий CSS теми може опинитись після CSS компонентів. Дай базовій бібліотеці явно меншу вагу замість того, щоб покладатись на порядок оголошення.

### Обробник теми спрацьовує для кожної форми на сторінці

Обробники, прив'язані до всієї сторінки (`$(document).on('click', '.webform-button--submit', ...)`), спрацьовують для всіх форм, зокрема в модальних вікнах і блоках. Обмеж їх обгорткою своєї форми.

### Карусель на мобільному показує краєчок наступного слайда

Зазвичай елемент, що обрізає (`overflow: hidden`), і елемент, від ширини якого рахуються слайди, — різні блоки: наприклад, слайдер обрізає поза padding сітки. Зроби межу обрізання й межу розміру одним блоком.

## Composer і патчі

### "Cannot apply patch", хоча патч виглядає правильним

1. Кінці рядків: із глобальним `core.autocrlf=true` файли патчів checkout-яться з CRLF. Перевір `file patches/<name>.patch | grep CRLF`; виправ `git config --local core.autocrlf input` і повторним checkout папки з патчами.
2. Версія: після merge або cherry-pick між гілками патч може бути написаний під іншу версію модуля, або повернувся запис, який гілка вже видалила.
3. Upstream: якщо `git apply --check -R --directory=web/modules/contrib/<module> <patch>` проходить, виправлення вже є в модулі; прибери запис патча.
4. Синхронізація mutagen у ddev може відставати: після правки `composer.json` зроби `ddev mutagen sync` і тільки потім запускай Composer знову.

## Конфігурація

### Часткові набори конфігу, які імпортуються без помилок

Для змін, що йдуть папкою з імпортом через `drush cim --partial --source=<folder>`:

- Прибирай `uuid`, `_core` і `langcode`: вони різні на кожному сайті й ламають імпорт.
- Генеруй файли з живого конфігу (`\Drupal::config($name)->getRawData()`), а не з папки експорту, яка може бути застарілою.
- Кожен набір має бути самодостатнім: додавай спільне field storage, навіть якщо воно є в іншому наборі, щоб набори імпортувались у будь-якому порядку.
- Нові залежності додавай у `dependencies.config`, інакше імпорт мовчки пропустить файл.
- `allowed_values` полів-списків у YAML — це список мап `{value, label}`; entity API натомість чекає ключований масив.
- Поле з найбільшою вагою опиняється в кінці форми; став його туди, де редактор його очікує.

### Конфіг у `config/install` не доходить до наявних сайтів

`config/install` модуля чи профілю читається лише під час його встановлення. Пізніша зміна нічого не робить на сайтах, де модуль уже стоїть; натомість постав імпорт конфігу або update hook.

### Single-value поля й фільтри з AND

Поєднання двох значень single-value поля через AND (`field = a AND field = b`) завжди дає порожній результат. У contextual filters Views кілька значень розбиваються взагалі лише з увімкненим "Allow multiple values" (`break_phrase`).

## Drush і користувачі

- Drush-команди тікетів мають жити в модулі, який проєкт уже використовує для команд, і бути зареєстровані в його `drush.services.yml`; команду в іншому модулі можуть просто не знайти.
- Якщо команда заповнює дані, яких потім вимагає зміна конфігу, спершу запускай команду, а потім імпортуй конфіг.
- Якщо `drush uli` не логінить, на сайті може бути власний контролер скидання пароля. Перевіряй сторінки адмінки скриптом від імені uid 1 (`drush php:script`).
- Повернення старішого коду на базу, вже оновлену під новішу major-версію Drupal, часто падає (бракує таблиць чи колонок новіших модулів). Це розбіжність бази, а не баг, який треба лагодити в коді.

## Back office через Playwright

- Перш ніж заповнювати поле, відкрий кожного згорнутого предка `<details>`.
- ID вузлів бери зі списку контенту, а не зі збереженої сторінки.
- В autocomplete вводь через `pressSequentially`, чекай близько 3 секунд і читай лише видимі підказки.
- Шукай поля за name, id або `data-drupal-selector`: мітки змінюються разом із мовою back office.
- Тестове чи preprod-середовище може переадресувати на production: блокуй переходи поза дозволеними хостами й записуй фінальний URL кожної дії.

## Фронтенд-тести

- Мобільна поведінка (tap, touch-події) відтворюється лише в context з `isMobile` і `hasTouch` та з `.tap()`; зміни розміру viewport недостатньо.
- Перед `.focus()` на елементі, що з'являється через CSS transition, зачекай два кадри анімації (подвійний `requestAnimationFrame`), інакше фокус губиться.
- Для пастки фокусу навколо груп radio реагуй на `focusin` і повертай фокус, замість того щоб заздалегідь рахувати перший і останній фокусовані елементи.
- Chrome може після зміни розкладки надіслати синтетичний `mouseleave` з хибними координатами; на малих екранах його ігноруй.

## Робота з тікетами з аудиту

Пакети пунктів з аудиту доступності чи іншого аудиту часто вже частково виправлені або описують те, що ніколи не було зламаним. Перевіряй кожен пункт на живому чи локальному сайті, перш ніж писати код.
