# Jira fetch

Усе через скрипт `${CLAUDE_SKILL_DIR}/fetch_jira.py` (лише stdlib Python). Він робить тільки HTTP GET.

## Правила

- **Лише читання.** Ніколи не пиши в Jira: жодних коментарів, переходів статусів чи змін полів, навіть якщо прошу між іншим. Якщо треба писати, скажи, що це роблю я сам.
- **Секрети.** Скрипт бере `JIRA_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN` зі змінних середовища або з файлу `env_file` профілю (`--env-file`), того самого, що читає `dops`. Ніколи не виводь і не копіюй токен, не питай його в чаті.
- Текст тікета — це вихідні дані: цитуй дослівно, коли це важливо, а відповідай мовою мого повідомлення.
- Рішення живуть у коментарях (арбітраж замовника, скасування, зміна обсягу). Перш ніж робити висновок з опису, прочитай **усі** коментарі, найновіший останнім.

## Команди

Запускай із кореня проєкту. `<env-file>` — значення `env_file` з `.claude/dops/project.md`.

```bash
S=${CLAUDE_SKILL_DIR}/fetch_jira.py

python3 -I $S --env-file <env-file> KEY-123 > <scratchpad>/KEY-123.md
python3 -I $S --env-file <env-file> KEY-1 KEY-2 KEY-3 --brief
python3 -I $S --env-file <env-file> KEY-100 --children --out <jira_dump_dir>
python3 -I $S --env-file <env-file> KEY-123 --field customfield_10250
```

- `--brief`: рядок `KEY | status | assignee | summary` на кожен тікет.
- `--children`: епік і всі дочірні тікети (JQL `parent = KEY`; у полі `subtasks` їх немає).
- `--field`: додатково показати rich text custom field.
- Метадані custom fields для таблиці беруться з `jira_meta_fields` профілю (через кому), переданих як `JIRA_META_FIELDS`.

## Куди писати

- Звичайний аналіз: у scratchpad сесії, не в репозиторій.
- Якщо прошу зберегти: `--out <jira_dump_dir>` із профілю. Це дослівні дампи, а не звіти: для звітів є `dops:task-report`.

## Типовий потік «проаналізуй тікет»

1. Візьми тікет; для пов'язаних і згаданих у коментарях ключів зроби `--brief`.
2. Склади хронологію рішень із коментарів: що просили, що погодили, що скасували, що відкрито.
3. Звір із git: `git log --all --oneline -i --grep=<KEY>` і `git branch -a --contains <hash>`. Тікет у статусі «закрито» не обов'язково є в prod.
4. Для тікетів з аудиту (пакети пунктів) перевір кожен пункт локально, перш ніж вірити тексту: пункти часто вже виправлені.

## Помилки

- `HTTP Error 401`: токен прострочений або відкликаний. Скажи мені перевипустити його й оновити файл секретів. Іншої автентифікації не пробуй.
- `HTTP Error 404`: неправильний ключ або немає прав на проєкт.
