# QA start (baseline)

Мета: зафіксувати стан сайту до змін, щоб `dops:qa-check` міг порівняти «до» і «після». Цей skill нічого не змінює в проєкті. Інструмент: `<dops_cli> visual` із профілю `.claude/dops/project.md`.

## Передумови

1. **URL set:** `<visual_set>` з профілю, описаний у `<toolkit_dir>/dops.config.yml` (`visual.urlSets`). Якщо його немає, зупинись і запропонуй `/dops:setup`. URL не вигадуй.
2. **Середовище:** за замовчуванням `baseUrl` URL set, тобто локальний сайт. Віддалене (`--env <name>` з `environments` URL set) лише якщо я явно назвав його в цьому запиті. Production без окремого явного рішення не знімай.
3. **Секрети:** basic auth береться лише зі змінних, названих у `httpAuth` URL set. Якщо змінної немає, скажи, яка потрібна. Ніколи не виводь значення.
4. **Node:** версія з `<toolkit_dir>/.nvmrc`.

## Кроки

1. **Сторінки.** З тексту тікета й аналізу в цій сесії визнач до 5 додаткових сторінок, яких стосується зміна, як шляхи на сайті (`/events`, не URL). Лише ті, які можеш обґрунтувати (тікет, маршрути, views у коді). Не впевнений: бери менше. Покажи список одним рядком.
2. **Чистота baseline.** Baseline знімається з того самого середовища, що й «after», і до того, як зміни туди потраплять. Якщо зміни тікета вже є в цьому середовищі, скажи, що baseline не чистий, і запропонуй інше середовище. Не роби stash чи checkout сам.
3. **Наявний baseline.** Якщо `<TICKET>-before` уже є, не перезаписуй: спитай, і лише за згодою додай `--force`.
4. **Запуск у фоні** (Bash з `run_in_background`), не чекай завершення:
   `<dops_cli> visual capture <visual_set> -l <TICKET>-before -p <path> -p <path> ...`
5. Скажи одним рядком: baseline запущено, N сторінок, середовище.
6. Коли завершиться, одним рядком: скільки сторінок і чи є зламані. Зламані сторінки (`broken` у виводі й у `meta.json` capture) означають, що baseline для них непридатний: назви їх і запропонуй виправити середовище до змін. Блокування переходу поза URL set — проблема налаштування середовища або `allowedOrigins`: повідом окремо.

## Правила

- Не блокуй мою роботу очікуванням.
- Не змінюй `dops.config.yml` без мого прохання (пропонуй зміни, наприклад `visual.hide`).
- Це свідчення, а не доказ. Висновків про якість змін на цьому етапі не роби.
