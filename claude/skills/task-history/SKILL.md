Таска: $ARGUMENTS

# Мета

Не пояснювати код, а відновити причинний ланцюг: чому поведінка така, яка вона є. Результат: висновок, чи це баг, і що робити.

# Процедура

1. **Таска.** Прочитай текст, усі коментарі, автора запиту, дату, acceptance criteria. Якщо в профілі проєкту (`.claude/dops/project.md`) є `tracker_url`, бери тікет через `dops:jira-fetch`. Якщо доступу немає, скажи, який саме текст потрібен, і не вгадуй.
2. **Код.** Знайди файл і функцію, де виникає симптом.
3. **Історія.** Для цих місць використай `git log -S`, `git log -L`, `git blame`. Витягни ключі тікетів (за `ticket_key_pattern` профілю) з комітів, гілок, PR.
4. **Пов'язані таски.** Підвантаж кожну знайдену таску (за наявності доступу), прочитай вимоги, коментарі, хто замовив, коли, яке рішення прийняли. Іди ланцюгом вглиб, поки не дійдеш до першоджерела вимоги, але не більше 3 рівнів без запиту.
5. **Зіставлення.** Порівняй: початкова вимога, поточна поведінка, вимога нової таски. Класифікуй:
   - (a) баг реалізації;
   - (b) вимоги змінилися або суперечать одна одній;
   - (c) замовник забув початкові умови;
   - (d) вимога була недовизначена;
   - (e) регресія від пізнішої зміни.
6. **Фікс і вплив.** Запропонуй 1-3 варіанти. Для кожного перевір, що ще використовує цей код (виклики, конфіг, views, update hooks, налаштування по сайтах у multisite, імпорт конфігу при деплої) і що може зламатися.

# Правила

- Розділяй **ФАКТ** (з коміту чи тікета, вкажи ключ або хеш) і **ГІПОТЕЗА**. Не вигадуй мотиви.
- Не описуй процес пошуку, лише результат.
- Не включай метадані тікета (статус, спринт, оцінка, assignee), історію чатів і стан локального середовища, якщо вони не впливають на висновок.
- Якщо вимога логічно або технічно невиконувана (наприклад, AND для двох значень одного single-value поля), винеси це окремим рядком у вердикті. Це головне, що я маю понести замовнику.
- Якщо не вистачає даних для висновку, постав 1-3 конкретні питання.
- Відповідай мовою мого повідомлення. Цитати з тікетів лиши в оригіналі.

# Формат виводу (разом до ~15 рядків)

1. **Вердикт** (1-2 речення): тип з (a)-(e), впевненість і, якщо є, невиконувана вимога.
2. **Хронологія** (3-7 рядків): дата, тікет, хто замовив, що змінилося.
3. **Чому так сталося** (1-3 речення).
4. **Варіанти фіксу** і що може зламатися.
5. **Що підтвердити** у замовника чи команди.
